# Permission-Based Sidebar System\n\nThis system implements permission-based visibility for sidebar menu items. If a user has ANY permission within a module, the sidebar item will be visible. If they have NO permissions within a module, the sidebar item will be hidden.\n\n## How It Works\n\n### 1. Backend Permission Structure\n\nPermissions are stored in the database with the following structure:\n- **name**: The permission identifier (e.g., `users.view`, `grn.create`)\n- **label**: Human-readable label (e.g., \"Users — View\", \"GRN — Create\")\n- **group**: The module/group name (e.g., \"User Management\", \"Goods Receipt & Inspection (GRN)\")\n\n### 2. Frontend Permission Utilities\n\n#### `src/utils/permissions.js`\nCore permission checking functions:\n- `hasPermission(permission)` - Check if user has a specific permission\n- `hasAnyPermission(permissions)` - Check if user has any of the provided permissions\n- `hasAllPermissions(permissions)` - Check if user has all of the provided permissions\n- `isAdmin()` - Check if current user is admin\n- `getCurrentUser()` - Get current user info from JWT token\n- `getUserPermissions()` - Get all permissions for current user\n\n#### `src/utils/sidebarPermissions.js`\nSidebar-specific permission functions:\n- `canViewSidebarItem(menuKey)` - Check if user can see a sidebar menu item\n- `getVisibleSidebarItems()` - Get all visible sidebar items for current user\n- `hasModuleAccess(group)` - Check if user has any permissions in a module\n\n### 3. Sidebar Implementation\n\nThe sidebar component (`src/components/Layout/Sidebar.jsx`) now:\n1. Imports the permission checking utility\n2. Adds `permissionKey` to each menu item\n3. Filters the menu array to show only items the user has access to\n4. Renders only the visible menu items\n\n## Usage Examples\n\n### In Components\n\n```jsx\nimport { hasPermission, hasAnyPermission, isAdmin } from '../utils/permissions';\n\nfunction MyComponent() {\n  return (\n    <div>\n      {/* Show content only if user has specific permission */}\n      {hasPermission('users.view') && (\n        <div>User list content</div>\n      )}\n      \n      {/* Show content if user has ANY of multiple permissions */}\n      {hasAnyPermission(['users.create', 'users.edit']) && (\n        <button>Create/Edit User</button>\n      )}\n      \n      {/* Show admin-only content */}\n      {isAdmin() && (\n        <div>Admin panel</div>\n      )}\n    </div>\n  );\n}\n```\n\n### Permission Keys for Sidebar Items\n\n- `dashboard` - Always visible\n- `userManagement` - User Management module\n- `organizationSetup` - Organization Setup\n- `itemMaster` - Item Master\n- `vendorMaster` - Vendor Master\n- `customerManagement` - Customer Management\n- `locationsManagement` - Locations Management\n- `purchaseManagement` - Purchase Management\n- `grn` - Goods Receipt & Inspection\n- `returnDisposal` - Return & Disposal\n- `vendorLedger` - Vendor Ledger\n- `stockLedger` - Stock Ledger\n- `externalTransfer` - External Transfer\n- `auditLog` - Audit Log\n- `dispensedItems` - Dispensed Items\n\n## Permission Groups\n\nEach sidebar item maps to specific permissions:\n\n### User Management\n- `departments.view`, `departments.create`, `departments.update`, `departments.delete`\n- `roles.view`, `roles.create`, `roles.update`, `roles.delete`\n- `users.view`, `users.create`, `users.update`, `users.delete`\n\n### Organization Setup\n- `company.view`, `company.create`, `company.edit`, `company.delete`\n- `branch.view`, `branch.create`, `branch.edit`, `branch.delete`\n- `store.view`, `store.create`, `store.edit`, `store.delete`\n- `department.view`\n\n### Item Master\n- `items.view`, `items.create`, `items.edit`, `items.delete`\n- `category.view`, `category.create`, `category.edit`, `category.delete`\n- `subcategory.view`, `subcategory.create`, `subcategory.edit`, `subcategory.delete`\n- `brand.view`, `brand.create`, `brand.edit`, `brand.delete`\n- `masterdata.setup`\n\n### Purchase Management\n- `purchase_request.view`, `purchase_request.create`, `purchase_request.edit`\n- `purchase_request.delete`, `purchase_request.status`, `purchase_request.send_po`\n- `purchase_order.view`, `purchase_order.print`, `purchase_order.download`\n\n### GRN (Goods Receipt & Inspection)\n- `grn.view`, `grn.create`, `grn.edit`, `grn.delete`\n- `grn.print`, `grn.status_qc`, `grn.status_approve`\n\n*And so on for other modules...*\n\n## Admin Users\n\nAdmin users have access to all sidebar items and permissions. They are identified by:\n- `user_type === 'admin'`\n- `role === 'admin'`\n- `is_admin === true`\n- `admin === true`\n- Having `'*'` in their permissions array\n\n## Adding New Sidebar Items\n\n1. **Add permission to backend** (`backend/utils/seed_permission.py`):\n   ```python\n   (\"new_module.view\", \"New Module — View\", \"New Module\"),\n   ```\n\n2. **Update sidebar permissions map** (`frontend/src/utils/sidebarPermissions.js`):\n   ```javascript\n   newModule: [\n     'new_module.view', 'new_module.create', 'new_module.edit'\n   ],\n   ```\n\n3. **Add menu item to sidebar** (`frontend/src/components/Layout/Sidebar.jsx`):\n   ```javascript\n   {\n     name: \"New Module\",\n     path: \"/app/new-module\",\n     permissionKey: \"newModule\",\n     icon: <YourIcon />\n   },\n   ```\n\n## Testing\n\nTo test the permission system:\n1. Create users with different role assignments\n2. Assign different permissions to roles\n3. Login with different users to see sidebar visibility changes\n4. Admin users should see all sidebar items\n5. Regular users should only see items they have permissions for\n\n## Security Notes\n\n- Frontend permission checks are for UI/UX only\n- Always implement proper permission checks on the backend APIs\n- JWT tokens contain user permissions for quick frontend checks\n- Permissions are validated on every API request on the backend
